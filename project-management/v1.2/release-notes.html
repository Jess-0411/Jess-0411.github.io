项目管理 V1.2 版本说明

发布日期：2026-09-05 · 技术发布标签：v1.2.9

教育局立项审批所需文件配置拆分

  • 教育局立项审批列表操作调整为“查看、所需文件、审批”，所需文件改为独立弹窗保存。
  • 审批弹窗不再包含文件勾选步骤；未配置所需文件时，审批前明确提示后续文件均按非必填处理。
  • 首位教育局审批人提交同意后锁定本轮文件要求；退回不锁定，学校重新提交后开启新一轮并允许调整。
  • 已锁定、已归档或非教育局待审批项目仅支持查看文件要求，并防止旧页面覆盖已生效配置。

v1.2.9 文件判定与补正反馈

  • 采购、开工、付款、验收、归档审批支持“合格 / 需补正”文件判定；未标记文件不阻止通过。
  • 选择需补正后填写文件原因，处理结果自动切换为退回申请人；确认处理后统一生效。
  • 申请端可定位、替换或删除问题文件，问题文件未处理及必填资料缺失时禁止重提。
  • 历次文件判定随审批记录保存；复核最新状态、权限及附件变化，保留现有演示数据。
  • 线上 V1.2 与本地 HTML 使用同一文件；附件仍为本地元数据模拟。

v1.2.8 五类业务直接审批

  • 项目办理仅保留立项办理与设计办理，删除采购、开工、付款、验收、归档五个办理标签。
  • 五项业务由学校直接提交教育局，不经过学校审批或教育局前置办理；具有对应页面审批权限的人员可直接通过或退回申请人。
  • 更新待审批业务统计和入口；历史学校待审批记录转为教育局待审批，保留原有审批、附件与办理历史。
  • 五项业务不受历史流程开关影响；保留立项和设计的原有流程。
  • 保留已有新增弹窗空白默认值、退回理由、全过程详情等本地改动。
  • 线上默认入口、独立 HTML 入口与本地 V1.2 project.html 采用同一文件，SHA-256 完全一致；返回版本选择链接按运行环境适配。
  • 继续使用 V1.2 localStorage 命名空间，不清空用户演示数据。当前版本为前端交互原型。

v1.2.7 本地版本同步补丁

  • 线上 V1.2 默认入口与独立项目入口同步本地最新 V1.2 单文件交互原型，业务功能、界面和数据逻辑保持一致。
  • 所有已退回、待重新提交的审批表单展示最近一次退回理由，覆盖立项、设计、采购、开工、付款、验收和归档。
  • 学校端与教育局端项目管理总览增加固定“操作”列，各阶段项目均可通过“查看详情”进入项目全过程详情。
  • 线上版本选择链接按部署环境转换，V1.0、V1.1 冻结文件及既有 V1.2 历史标签保持不变。

v1.2.6 无刷新导航体验补丁

  • 项目管理内部菜单、详情、标签及端别切换改为 History API 单页导航，不再重新加载整份单文件。
  • 侧栏、顶栏、React 数据上下文与页面级状态持续保留，仅业务内容区按新地址更新。
  • 内容区切换使用 120ms 轻淡入；系统开启“减少动态效果”时自动禁用动画。
  • 浏览器前进、后退及原有深链继续按端别、页面、详情和标签参数恢复，并保持 V1.2 schema v8 演示数据不变。

v1.2.5 最新本地版本同步

  • 线上 V1.2 默认入口与独立项目入口同步本地最新 V1.2 单文件交互原型。
  • 学校端、教育局端及历史深链继续通过端别和页面参数进入同一份项目全过程应用。
  • 继续使用 education-project-lifecycle-prototype-v1.2-v8 存储命名空间，不清除既有演示数据。
  • 发布过程继续校验 V1.0、V1.1 冻结文件，历史版本内容保持不变。

v1.2.4 单文件线上同步

  • 线上 V1.2 默认入口与独立项目入口统一加载最新单文件交互原型，页面结构、样式和业务交互与本地 V1.2 HTML 保持一致。
  • 原学校端、教育局端深链继续可访问，并自动携带对应端别和页面参数进入单文件应用。
  • 原线上 education-project-lifecycle-prototype-v8 数据首次加载时迁移至 V1.2 独立命名空间，旧数据键保留用于回滚。
  • 版本选择页、发布说明和发布元数据统一更新为 v1.2.4，V1.0、V1.1 历史版本保持冻结。

教育局自建项目部门审批

  • 新增项目管理科、财务科、发展规划科三组教育局经办人与部门审批人演示身份。
  • 教育局自建项目的立项、设计、采购、开工、付款、验收、归档按每次提交人的所属部门分配审批人，并禁止提交人审批本人记录。
  • 退回后可由其他部门经办人修改并重新提交，审批部门与审批人按本次提交身份重新生成快照。
  • 教育局自建项目仅在教育局端可见；即使选填关联学校和场地，学校端列表、统计、阶段页及直接详情地址均不可访问。
  • 会议、合同、进度、发票由教育局经办人直接登记维护，并记录实际操作人和操作时间。

v1.2.3 菜单补齐补丁

  • 恢复“项目招投标”一级菜单，并提供“采购管理、合同管理”二级入口。
  • 恢复“项目实施”一级菜单，并提供“项目开工、项目进度”二级入口。
  • 恢复“资金管理”一级菜单，并提供“付款管理、发票管理”二级入口。
  • 以上入口复用 V1.2 已有全过程页面与 schema v8 数据。

v1.2.2 审批设置补丁

  • 学校端下线“审批配置／审批设置”入口；旧 view=workflow 地址统一回到全流程查看管理页。
  • 教育局端仅在当前审批页面实际存在学校来源、教育局审批中的记录时显示“审批设置”。
  • 立项、设计、采购、开工、付款、验收和归档分别支持“首次审批人”与“固定审批人”规则。
  • 固定审批人可从王科长、刘老师、赵主任中搜索并单选；非指定身份不展示对应学校项目待办。教育局自建项目独立按提交人部门分配，不受学校项目审批设置影响。
  • 审批设置即时作用于未完成的学校项目局审待办，历史审批轨迹保持不变；一键重置恢复七阶段默认首次审批人规则。

v1.2.1 交互补丁

  • 项目管理页头新增“学校端／教育局端”双选分段按钮，当前端保持高亮。
  • 切换学校端时使用张老师维护身份，切换教育局端时使用陈老师项目管理科经办人身份。
  • 端别切换后统一进入目标端全流程查看管理页，头像菜单中的细分演示身份继续保留。

项目立项改版

  • “项目立项”调整为一级菜单，页面统一展示“项目立项”和“项目审批”两个标签页。
  • 项目立项列表支持按项目名称、项目负责人、审批状态和创建时间区间组合查询，并支持一键重置。
  • 学校端和教育局端均支持新增、查看及按状态编辑项目，新增或提交后自动返回项目立项列表。
  • 项目审批沿用 V1.1 列表与审批交互，支持必填审批意见、模拟附件以及通过、退回申请人和退回上一节点。
  • 旧版项目审批地址继续兼容，审批结果、审批轨迹和操作记录在双端共享的 localStorage 数据中同步更新。

本次重构

  • 学校项目与教育局直属项目统一覆盖立项、设计、会议、采购、合同、开工、进度、付款、发票、验收和归档 11 个阶段。
  • 学校端与教育局端使用七组一致的信息架构，并按项目来源、经办主体和审批节点控制查看与维护权限。
  • 设计版本、会议、采购、合同、进度、付款和发票支持多记录维护；采购、合同、付款和发票具备上下游引用及金额限制。
  • 立项、设计、采购、开工、付款、验收和归档按单笔记录执行学校／教育局审批，支持通过、退回申请人和退回上一节点。
  • 项目编号改为经办人手工必填并统一校验唯一；已审批业务只读，退回记录允许修改重提。
  • 保留 V1.1“更新采购”能力，并校验公告、投标、中标时间顺序和中标金额。
  • 按确认脑图配置 21 项所需文件，各阶段支持补充附件；文件仅保存元数据和临时预览信息。
  • 归档缺项仅汇总提示，经二次确认仍可提交；归档审批通过后项目整体只读。
  • 前端存储升级为 schema v8，兼容迁移旧项目、审批轨迹、附件和原审批开关，并提供一键重置演示数据。

数据隔离

V1.2 使用 education-project-lifecycle-prototype-v1.2-v8 独立存储键，并兼容迁移原线上 education-project-lifecycle-prototype-v8 及 schema v7、v6、v5 数据；迁移过程不删除旧键，不读取或覆盖 V1.0、V1.1 演示数据，V1.2 内学校端和教育局端共享同一份浏览器数据。

原型限制

本版本为纯前端静态交互原型，不包含真实后端、数据库、登录鉴权、文件服务器、支付、发票查验和第三方接口。
